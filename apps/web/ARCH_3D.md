# DIAMOND Genome UI rebuild — architecture contract

Goal: world-class 3D redesign. Full-bleed react-three-fiber scene (fixed, z-0) behind a glassmorphism HUD (z-10). Aesthetic: dark deep-space biotech, cyan/violet neon, frosted glass (`.glass`, `.glass-strong`, `.hud-label`, `.hud-title`, `.neon-text`, `.enter` classes in src/index.css), mono HUD typography, restrained motion, high contrast, a11y (aria, focus rings, keyboard, reduced motion).

Stack (do NOT upgrade/add deps): React 18, three 0.165, @react-three/fiber 8, drei 9, @react-three/postprocessing 2.16, maath, zustand 4, tailwind 3, lucide-react, vitest. Work dir: /home/923873155/Diamond_Proj/apps/web.

## Rules
1. You own EXACTLY the file(s) listed for you. Never edit any other file. If you need something from another file, use the contract below; if the contract lacks it, work around inside your own file.
2. Keep the exported name and signature in the table (other agents import it right now). Stubs already exist; replace the stub body.
3. Store: `src/stores/useGenomeStore.ts` is frozen (read only). Components are store-driven with zero props unless the table says otherwise. Shared helpers: src/lib/colors.ts, src/lib/format.ts (frozen).
4. Layout contract: HUD stage is `fixed` between top bar (var(--hud-top)=3.5rem) and bottom dock (var(--hud-bottom)=4rem), `pointer-events-none`; every panel uses `.glass` (re-enables pointer events). Views leave the screen center clear so the 3D shows. Must work from 1024px up and degrade gracefully on narrow screens.
5. 3D contract: scene components render inside one shared <Canvas>, no props, read the store, use useFrame cheaply (no per-frame allocations, instancing for repeated geometry, dispose what you create). Helix local frame: radius 1.25, height 14 (y -7..7), 3.5 turns, group centered at origin. Scene components that are mode specific must return null otherwise. Respect `useQuality()` (lib/quality.ts) and reducedMotion. Never use Math.random during render (use seeded/useMemo).
6. Other agents are editing their files simultaneously, so `npx tsc --noEmit` may show errors in files that are not yours: ignore them, but make sure there are NO type errors in your own files (filter: `npx tsc --noEmit 2>&1 | grep <your-file>`). Do not run `npm install`, git commands, or dev servers. Do not run the full vitest suite expecting green on others.
7. Keep existing behaviors (API endpoints, data flow) intact when rewriting existing files. Quality bar: production-grade, no placeholders/TODOs, no dead code, comments only when non-obvious.
8. Final reply: 3 lines max — what you built, any contract gaps/risks for the integrator.
