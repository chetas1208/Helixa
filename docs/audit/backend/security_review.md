# Audit: security_review (read-only, cross-cutting review of services/)

Scope: path traversal in fixture/artifact resolution, subprocess allowlisting, secret leakage in logs/responses, CORS/middleware, SSE abuse, input size limits, ObjectId leakage. No source file was changed (read-only unit). All reproductions were run against the current working tree through the real FastAPI `app` (Starlette `TestClient` / direct ASGI calls) from a scratch working directory (copy of `fixtures/`, own `artifacts/`) with `MONGODB_DATABASE=diamond_audit_security_review` (dropped afterwards). No network, no `diamond_genome` access, no git writes. Repro scripts live in the session scratchpad, not in the repo; the exact request for each item is given inline. Items already fixed or already listed by other units were re-read against current code; those that are still live are cross-referenced.

Threat model used: the API is meant to run on 127.0.0.1 (Makefile `--host 127.0.0.1`; compose publishes `127.0.0.1:8000`; mongod bound to 127.0.0.1, verified with `ss -ltn`). The realistic attackers are (a) any web page open in the developer's browser, (b) other local users/processes, (c) a mis-deployment that binds a public interface (the Dockerfile CMD binds 0.0.0.0 inside the container).

## FIXED

None. This unit is read-only; no code, test or config was modified.

## CONFIRMED (reproduced; needs the owner named in each item)

C1. No authentication or authorization on any route, including every mutating one. Mutating routes: `POST /api/datasets/upload`, `POST /api/runs`, `POST /api/runs/{id}/evolve`, `POST /api/runs/{id}/investigate`, `POST /api/validation/run`, `GET /api/validation/{id}/stream` (it persists a run), `POST /api/capabilities/register|{id}/activate|{id}/quarantine`, `POST /api/voice/briefing`. Reproduced: every one of them answered 200 with no credentials. Whether this is acceptable is a deployment decision (local research tool); it becomes severe if the process is ever bound beyond loopback (Dockerfile CMD uses `--host 0.0.0.0`). Owner: api_core (a shared token/Host guard) plus each route owner.

C2. CSRF from any origin for body-less and multipart POSTs (CORS only stops reading responses, it does not stop the write). Requests, all with `Origin: https://evil.example`:
   - `POST /api/capabilities/run_validation/quarantine` -> 200, built-in primitive `run_validation` is now `status: quarantined` (confirmed by a follow-up GET). Same shape applies to `/activate`, `POST /api/runs/{id}/evolve`.
   - `POST /api/datasets/upload` as `multipart/form-data` (a "simple" cross-site request, no preflight) -> 200 `INGESTED`, file written to `artifacts/cas`.
   - JSON-body POSTs (`/api/runs`, `/api/validation/run`, `/api/capabilities/register`) are NOT cross-site exploitable today: with no `Content-Type` or `text/plain` FastAPI 0.143 returns 422, and `application/json` forces a preflight that CORS rejects (400, no `access-control-allow-origin`, verified). This protection is incidental to the framework version, not a deliberate control.
   - Fix direction (not applied): reject non-allowlisted `Origin` on non-GET requests in middleware. Owner: api_core.

C3. No `Host` header validation (DNS-rebinding exposure). `GET /api/health` with `Host: attacker.example:8000` -> 200. Combined with C1, a rebinding page can read every GET endpoint (runs, events, evidence, datasets) as same-origin. The rebinding step itself needs attacker DNS and was not demonstrated; the missing Host check is what was reproduced. Owner: api_core (`TrustedHostMiddleware` with 127.0.0.1/localhost allowlist).

C4. API-triggered runs bypass the lease/fencing path (ADR-002 not enforced on the HTTP route), so an unauthenticated client can replay a run's pipeline. Reproduced: create one run, then 3 concurrent `POST /api/runs/{id}/evolve` -> three 200s; the event log for that single run contains `run.created` x3, `candidate.promoted` x3, `evaluation.finished` x3, `run.completed` x3 (sequence numbers stay gapless, ADR-003 holds, but the provenance is duplicated). Cause: `runs.py` calls `AgentRunner.execute_run(... fence_token=None)`; `execute_run` itself is not idempotent for non-finished runs. Already noted by route_runs as UNVERIFIED; re-confirmed here against current code. Owner: orch_runner / route_runs.

C5. Missing request-size and field-size limits.
   - Upload: Starlette spools the whole multipart body before the handler runs; the 25 MB cap is applied only while copying. Reproduced: a 60 MB upload returns 413, but `file.file` already held 62,914,641 bytes when `stream_and_persist` was entered. No ASGI-level `Content-Length` cap exists. Distinct uploads are unlimited (two different files were both accepted; there is no CAS quota or count cap), so repeated 25 MB uploads fill disk. Owner: api_core (body-size middleware), route_datasets.
   - JSON fields: no max lengths. Reproduced: `POST /api/capabilities/register` with an 8 MB `description` x3 -> 200 each, registry entries grew 9 -> 12 (in-memory, unbounded, never evicted); `POST /api/runs` with a 2 MB `task_id` -> 200 (persisted); `POST /api/validation/run` with a 2 MB `dataset_id` -> 200. Owners: api_schemas / route_runs / route_validation / route_investigations_capabilities.

C6. Unenforced record limit makes a small upload an expensive, loop-stalling request. `FileIngestionService.max_records=50000` is never enforced (also noted by gen_ingestion). Reproduced: upload of a 3.8 MB VCF with 100,000 records then `POST /api/validation/run` on its CAS name took 7.2 s; a concurrent `GET /api/scene/state` scheduled with a 0.5 s timer completed after 1.78 s (the event loop was blocked ~1.3 s). A 15.2 MB / 400,000-record file took 29.8 s for one request. All of this is reachable unauthenticated (C1). Owner: gen_ingestion / route_validation (enforce limit, run blocking work in a thread).

C7. SSE abuse. `GET /api/runs/{id}/stream` accepts any `id`: for an unknown run it streams `: ping heartbeat` forever (reproduced: status 200, heartbeats until the client disconnects). 300 concurrent streams for 300 nonexistent runs were all accepted (300/300 status 200); each connection issues a Mongo query per second. No per-client cap, no maximum lifetime, no existence check. Also already noted by route_runs. Owner: route_runs / api_core.

C8. Absolute server filesystem paths are returned to clients (discloses the OS user and home layout). Reproduced:
   - `POST /api/datasets/upload` response `artifact.storage_path`, and `GET /api/datasets/{id}` `fixtures.primary_artifact`, both `/<abs>/artifacts/cas/<sha>.vcf`.
   - `GET /api/validation/{run_id}` returns the stored run document with `tool_receipts[0].argv[1]`, `.args[1]`, `tool_traces[0].argv[1]` = absolute path of the VCF (the POST `/run` response and `/evidence` do not contain it).
   - Conditional: `GET /api/v8/health` -> `ebi_vcf_validator.detail` embeds the absolute binary path when the pinned binary is missing (seen in the scratch cwd; with `third_party/` present the detail is the static "checksums match" string).
   Already noted for datasets by route_datasets. Owners: route_datasets, route_validation, int_ebi.

C9. Unhandled 500 on over-long filenames (robustness, no data leak: body is the generic "Internal Server Error"). `POST /api/validation/run {"vcf_filename": "a"*5000}`, `GET /api/validation/x/stream?vcf_filename=aaaa...(5000)`, and `POST /api/runs/x/investigate {"vcf_path": "fixtures/" + "a"*5000}` all return 500: `Path.is_file()` raises `OSError(ENAMETOOLONG)`, which `_is_allowed_file` / `_resolve_input_file` do not catch (`runs.py` caps names at 255, these routes do not). Owners: route_validation, route_investigations_capabilities.

C10. Held-out fixtures can be run through the public API and their outcomes read. `POST /api/validation/run {"vcf_filename": "unseen_mismatch.vcf"}` -> 200 with `status: FAIL` and findings (`reference_ref_allele_match: FAIL`); `POST /api/runs/x/investigate` with `fixtures/heldout/unseen_mismatch.vcf` -> 200 with error signature and artifact sha. ADR-017 scopes held-out isolation to proposer inputs (`assert_proposer_inputs_exclude_holdout`), and no API route feeds the proposer, so I do not claim an ADR violation; but the `/api/fixtures` contract withholds held-out outcomes, and these two routes disclose them. Policy decision needed (resolve_fixture_path could exclude `fixtures/heldout` and sealed v7 cases). Owners: route_validation / eval_holdout.

C11. `sanitize_mongodb_uri` (client.py:29-33) masks only `user:password@`. Secrets in the query string are returned as-is: `mongodb://h/?tlsCertificateKeyFilePassword=SECRET1&authMechanismProperties=AWS_SESSION_TOKEN:TOK2` is unchanged. The sanitized URI is returned by `GET /api/integrations/status` (`mongodb.uri`) and used in log lines/exception text, so such a configuration would leak. Atlas `user:pass@` URIs (the documented format) are masked correctly, including `@` in the password and multi-host lists, so this is a hardening gap, not a hit on the supported config. Owner: mongo_client.

C12. ADR-013 telemetry scrub is narrower than its text claims ("mathematically guarantees zero genomic ... leakage"). Reproduced against `RaindropAdapter._sanitize`: a nucleotide string broken by spaces or dashes (`"ACGT ACGT ACGT ACGT ACGT"`, `"ACGT-ACGT-ACGT-ACGT"`) passes unredacted; locus and alleles in free text (`"REF mismatch at chr22:10001 A>G expected C"`) pass unredacted by design; a non-`str` dict key raises `AttributeError` (`_sanitize({1: "x"})`). Telemetry is disabled by default (ADR-018) and the ADR threshold is "16 or more nucleotide letters", so this is a documentation/limit gap rather than a regression. Owner: int_raindrop (and an ADR clarification).

C13. Interactive docs are served in all environments: `GET /docs`, `/redoc`, `/openapi.json` -> 200. Information only (full route and schema map); Swagger UI page loads assets from a CDN. Owner: api_core.

C14. `POST /api/runs/{id}/evolve` is registered twice (runs.py and investigations.py); the first-included wins and the investigations handler is unreachable (reproduced: body `{"failure_finding": ...}` gets runs.py's 404 `Run 'x' not found`). Not a vulnerability by itself, but it means the reachable evolve route is the one that bypasses fencing (C4). Already noted by api_core and route_investigations_capabilities.

## UNVERIFIED/NEEDS OTHER OWNER

U1. services/integrations/ebi_vcf/validator.py:51,175,298 and services/runtime/genomics/bcftools_adapter.py:115: untrusted uploaded VCF/FASTA bytes reach native parsers (htslib via pysam and bcftools, EBI `vcf_validator` / `vcf_assembly_checker`) in the API's own process or as the API user, with wall-clock timeouts only. The EBI class docstring claims "resource limits" but no rlimit/cgroup is applied, the EBI call inherits the full parent environment (bcftools correctly passes only `LC_ALL`/`PATH`), and `subprocess.run(capture_output=True)` buffers all stdout/stderr in memory. A memory-exhausting or crashing input is plausible but I did not reproduce one (I did not feed hostile input to the real EBI binaries), so no claim is made.

U2. services/integrations/ebi_vcf/validator.py:85-93 and :99: the pinned SHA-256 is checked on one `read_bytes()` and the binary is executed later (TOCTOU window); each `is_available()` rehashes ~7 MB binaries (also the cause of the `/api/v8/health` stall noted by route_v8). Exploiting the window requires write access to `third_party/`, so it is not a remote issue. Not reproduced.

U3. services/runtime/genomics/bcftools_adapter.py:39: default `bcftools_path` is the hard-coded `/home/923873155/.local/bin/bcftools`, outside the repo; it is a Python pysam shim, not the real bcftools. Any process running as that user can replace it, and ADR-005's "independent" cross-check then shares htslib with pysam. Environment/provenance issue; `_norm_sets_ref` was probed against bcftools `norm --help` of the bundled version (`-N[NUM]`, `-W[=FMT]` optional args; lowercase `s` is a no-arg flag) and its spelling coverage (`-cs`, `-c s`, `--check-ref[=]s`, abbreviations, `-acs`) looks correct, so I found no `--check-ref s` bypass.

U4. services/integrations/raindrop/adapter.py:73,130: `_mock_traces` appends every dispatched record even when disabled and is never trimmed (reproduced on one instance: 2 calls -> 2 retained). All in-tree call sites build a short-lived adapter per request, so there is no demonstrated leak; a long-lived instance would grow without bound.

U5. services/api/app/routes/voice.py (ERROR branch `str(e)`) echoes the upstream ElevenLabs error body to the client; the API key is only sent as a request header and is not in that text (route_voice analysis agrees). Not a key leak; left as vendor-detail exposure.

U6. Deployment: `services/api/Dockerfile` runs as root and binds 0.0.0.0 in the container (compose publishes only 127.0.0.1); mongod runs without authentication (loopback only). On a shared multi-user host any local user can read/write both. Configuration decision, not verified as exploitable in this environment.

U7. services/api/app/routes/validation.py:110-130: `/{id}/stream` accepts a caller-chosen `id` that is stored as a run id and receipt run id; its 409 guard is check-then-act (race already noted by route_validation). I could not construct a collision with server-generated ids (`run-<epoch>-<12 hex>`), so no impersonation of another run was shown.

## VERIFIED OK

- Path traversal in fixture/artifact resolution (`resolve_fixture_path`, `/api/validation/run` and `/stream`): `../../etc/passwd`, `/etc/passwd`, `//etc/passwd`, `..`, `valid/../../secret.txt`, `fixtures/../secret.txt`, an absolute path to a file outside the roots, a NUL byte, glob metacharacters (`*`, `**/*.vcf`) and a symlink inside `fixtures/valid` pointing to `/etc/passwd` were all rejected with 404 (resolved-path `is_relative_to` check). Same for `POST /api/runs/{id}/investigate` (`/etc/passwd`, `fixtures/../../etc/passwd` -> 400). `runs.py` `_check_filename` blocks `..`, `/`, `\`, NUL and >255 chars before the runner joins names onto `fixtures/invalid|valid|references`. Evidence-seal ids: `..%2F..%2Fetc%2Fpasswd` and `..` -> 404 (regex plus fixed `.json` suffix).
- Upload filename handling (ADR-011): traversal names are rejected before any write; CAS names derive from SHA-256, never from the client filename; gzip bomb and over-limit paths clean the temp file (route_datasets / gen_ingestion tests).
- Subprocess surface: the only `subprocess` users in `services/` (non-test) are `BcftoolsAdapter._execute` and `EbiVcfValidator` (`get_version`, `validate` x2). All use argument lists (no `shell=True`), absolute resolved input paths (no leading `-`), timeouts that kill the child, and bcftools additionally has a subcommand allowlist, `--check-ref s` guard, `LC_ALL/PATH`-only environment and an isolated cwd. No `os.system`, `eval`, `exec`, `pickle`, `yaml.load` or dynamic imports of request data exist in `services/` (the one `importlib.import_module` takes names from a fixed tuple). The Biomni adapter is not imported by any route (ADR-014).
- Injection: all route parameters reaching Mongo are `str`/`int`/`Enum`-typed Pydantic or path values used as equality filters; `{"task_id": {"$ne": null}}` -> 422. No request-built query dicts, `$where`, `$regex` or aggregation from user input.
- ObjectId / BSON leakage (ADR-004): after creating a run, evolving it, running validation and uploading a dataset, I fetched `/api/health`, `/health/ready`, `/integrations/status`, `/datasets`, `/runs/{id}`, `/runs/{id}/events`, `/runs/{id}/findings`, `/validation/{id}`, `/validation/{id}/evidence`, `/evidence/{receipt|run}`, `/harnesses`, `/harnesses/{id}/lineage`, `/fixtures`, `/capabilities`, `/v8/health`, `/v8/latest`, `/scene/state`, `/experiments/v7` and scanned recursively for `_id` keys and 24-hex ObjectId strings: none. All repository reads project `_id: 0`.
- Secrets in responses/logs: `/api/integrations/status` returns the sanitized Mongo URI and exposes the Raindrop endpoint / ElevenLabs voice id only when `CONFIGURED`; no API key, write key or password appears in any response; `.env` is git-ignored and untracked (`git check-ignore`), `.env` keys are empty for MODEL/RAINDROP/ELEVENLABS and both sponsor integrations are disabled; a repo-wide scan (excluding node_modules/.venv/.research) found no real key, token or private key, only test fixtures with fake credentials. No log call interpolates request-controlled values (log lines contain only server-side ids, worker ids and exception text); the unhandled-exception handler returns a generic body with the security headers.
- CORS: only `http://127.0.0.1:5173` and `http://localhost:5173` are allowed (preflight from `https://evil.example` -> 400 and no `access-control-allow-origin`; a simple GET from an evil origin gets no ACAO); methods limited to GET/POST/OPTIONS; credentials allowed only for those two origins. Security headers (`nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`) are present on normal, 404 and 500 responses.
- SSE: event names and data are server-produced and `json.dumps`-encoded on one line (no event-stream injection from request data); `Last-Event-ID` is accepted only if ASCII digits within int64; `after_seq` bounded to int64; disconnect is honored in both stream generators.
- Evidence sealing / read-only surfaces: the seal routes only read `artifacts/v7/seals/<regex-validated>.json`; there is no HTTP route that writes or alters seals, receipts or harness specs, so V7-ADR-003 integrity cannot be altered through the API. `--check-ref s` remains forbidden (ADR-007) and `/api/capabilities/register` still rejects `eval`/`exec`-style macro mappings (V7-ADR-002).
- Network/SSRF: the only outbound HTTP clients (Raindrop, ElevenLabs, the model provider) build URLs from environment configuration, never from request data.
- Network exposure of the dev stack: API, web and mongod listen on 127.0.0.1 only (verified with `ss -ltn`).
- Tests run for this unit: none added (read-only). `ruff` and pytest were not required for a doc-only unit; the only file written is this document, and the temporary Mongo database `diamond_audit_security_review` was dropped after the reproductions.

## Follow-up after this review

Closed on 2026-10-11, with tests:

- C2: a non-GET request that sends `Origin` outside `http://127.0.0.1:5173` and `http://localhost:5173` is rejected with 403. Requests with no `Origin` are unchanged.
- C3: `Host` values other than `127.0.0.1`, `localhost`, `testserver`, and `test` are rejected with 400. `test` and `testserver` stay allowed so the ASGI test clients keep working.
- C4: `AgentRunner.execute_run` claims an `executing` flag. A second caller does not walk the pipeline. Resume after an exception still runs, because the flag is cleared in `finally`.
- C9: over-long paths that raise `OSError` from `Path.is_file` are answered as 400 or treated as not allowed, instead of an unhandled 500.

Still open, and not treated as fixed: C1 (no authentication), C5 (body and field size), C6 (record-count limit), C7 (SSE on unknown run ids), C8 (absolute paths in responses), C10 (held-out fixtures reachable from validation routes), C11 (Mongo URI query secrets), C12 (nucleotide runs split by spaces), C13 (interactive docs), C14 (duplicate evolve registration).
