# Audit: v8_experiment (services/runtime/v8/experiment.py)

## FIXED
1. experiment.py `run_campaign` (fresh-start branch, line 100-101): a fresh (non-resume) run in an output directory that already held a promoted campaign was always REJECTED with `promotion_writes` 0. `v8_active_pointers` still pointed at the earlier candidate, so `claim_promotion(parent -> candidate)` failed. Failing test: `test_fresh_rerun_in_same_output_dir_is_not_blocked_by_stale_pointer`. Fix: `_reset_active_pointer(out)` deletes that namespace's pointer document whenever the campaign starts with no completed stage (it reuses `checkpoint_store._client`, `_database_name`, `namespace_for`).
2. experiment.py promotion block (line 305): after a successful `claim_promotion`, a failure before `finish("promoted")` left the checkpoint at the parent version while the pointer had moved. On resume the second claim failed and the campaign reported REJECTED although the pointer was already on the candidate. Failing test: `test_resume_after_failure_following_pointer_claim_still_reports_promotion`. Fix: `_save_state` right after the claim, so resume takes the existing `active_version_id == chosen_id` branch.
3. experiment.py receipt `safety_gates.input_not_rewritten` (line 330): hard-coded `True`. It is now `compute_sha256(vcf) == manifest["incident_sha256"]`, so the receipt cannot assert an unverified gate. Failing test: `test_input_not_rewritten_gate_is_computed_not_asserted`. Unchanged inputs still give `True` (existing tests pass).
4. experiment.py `_write` (line 41): non-atomic `write_text` could leave a truncated `checkpoint.json` or artifact after a crash, which made `_load_state` raise `JSONDecodeError` on resume (and let readers such as routes/v8.py see partial files). Failing test: `test_failed_write_leaves_previous_json_intact`. Fix: write to `<name>.tmp`, then `os.replace`; the temp file is removed on failure.

## UNVERIFIED/NEEDS OTHER OWNER
- experiment.py `finish()` (line 104-117) and the `finish("promoted", ...)` call (line 426): the INTERRUPTED return value of the last call is discarded, so `crash_after="promoted"` returns COMPLETED. `interrupted_after` also stays in the checkpoint after a later successful resume. This is the test hook only, with no scientific effect, and its intended semantics are unclear, so it was left unchanged.
- experiment.py receipt decision: with fix 3, a failed `input_not_rewritten` gate is recorded truthfully, but the decision (PROMOTED/REJECTED) does not depend on it. Whether a rewritten input should block promotion is a policy decision. Also, `holdout_isolated: True` is a constant; the HoldoutLeakError guard at line ~174 runs first, so it holds in practice.
- experiment.py `_reset_active_pointer` uses private helpers of checkpoint_store.py (owner v8_store_contracts). A public `reset_pointer` there would be cleaner. Two campaigns started fresh on the same output dir at once would defeat the single-writer claim, but they already share all output files and this was not treated as supported.
- A crash in the narrow window between `claim_promotion` returning and the new `_save_state` still loses the claim. Closing it needs a pointer read API in checkpoint_store.py (other owner).
- experiment.py:37-38 `INCIDENT_FIXTURE` / `REFERENCE` and `fixtures_root` are caller-supplied, not request-controlled (only scripts and tests call `run_campaign`), so no traversal surface.
- `crash_after` is ignored when the named stage was already completed (resume path); test hook only.

## VERIFIED OK
- Resume reuse: each stage loads its effect from the checkpoint instead of recomputing (evaluation runs once, `eval_runs == 1`); `promotion_writes` stays 1 across repeated resumes.
- `_load_state` prefers MongoDB only when it has at least as many completed stages as the file; falls back to the file or a fresh state.
- Held-out isolation: `assert_proposer_inputs_exclude_holdout` runs before proposing; held-out fixtures are scored only by IndependentEvaluator; `meta_harness_imported` and `gepa_optimize_called` are false (ADR-015, ADR-017).
- The unsafe candidate (extra `execute_shell` tool, contig check disabled) is rejected by PolicyEnvelope and never evaluated; evaluation only covers accepted candidates that enable the REF-allele check.
- Receipt digest is minted by `mint_v8_receipt` and re-verified; the ElevenLabs briefing contains no nucleotide runs and is not automatic; Raindrop and ElevenLabs are constructed disabled (ADR-018). `build_identity_proven` stays False.
- Tests: services/tests/test_audit_v8_experiment.py (4 tests, own db `diamond_audit_v8_experiment`, dropped afterwards, tmp_path outputs only); test_transfer_ablation.py, test_optimizer_gate.py, test_audit_route_v8.py, test_audit_v8_store_contracts.py pass; ruff clean.
