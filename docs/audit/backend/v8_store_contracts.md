# Audit: v8_store_contracts (services/runtime/v8/checkpoint_store.py, contracts.py, __init__.py)

## FIXED
- checkpoint_store.py `save_checkpoint`, `load_checkpoint`, `claim_promotion`: the `MongoClient` was closed only on the success path. When `ping` or the collection operation raised `PyMongoError` (the normal offline fallback), the client was never closed, leaking its monitor threads and sockets on every call. Failing tests: `test_save_checkpoint_closes_client_on_error`, `test_load_checkpoint_closes_client_on_error`, `test_claim_promotion_closes_client_on_error` (6 parametrized cases failed before the fix). Fix: `client = None` before the `try`, and `close()` in a `finally`. Return values and the error-to-fallback mapping are unchanged.

## UNVERIFIED/NEEDS OTHER OWNER
- NEEDS v8_experiment OWNER (experiment.py:62-75, 276): a fresh campaign (`resume=False`) into an output directory that already ran never resets the `v8_active_pointers` document. Reproduced with a local audit DB: `run_campaign(out)` twice into the same directory gives `promoted=True` (`active_version_id=harness-v1-mh-hardened-...`) and then `promoted=False`, `active_version_id=harness-v1`, `promotion_writes=0`. The second run's `claim_promotion(out, "harness-v1", candidate)` finds the pointer already on the candidate and returns False. `scripts/demo_v8.py` calls `run_campaign` fresh each time into `artifacts/v8`, so a repeated demo against a persistent DB would record REJECTED. The fix belongs in the experiment (reset the pointer when starting a non-resume run) or needs a new store API, so it was not changed here.
- checkpoint_store.py:72-92 `claim_promotion` is not idempotent for the same candidate. A crash after the pointer moves but before the `promoted` stage is checkpointed leads, on resume, to `claim_promotion(parent, candidate)` returning False and a REJECTED decision while Mongo shows the candidate active. Making a same-candidate retry return True would also let two concurrent writers that pick the same content-addressed candidate both win, which breaks the documented one-writer rule (ADR-020). A design decision, so unchanged.
- checkpoint_store.py:79-83 The pointer is seeded with `update_one(upsert=True)` and there is no unique index on `namespace`. Two concurrent first claims could create duplicate pointer documents and both succeed. Not reproduced deterministically; adding an index is a behavior change outside the bug evidence.
- checkpoint_store.py:33-52 `save_checkpoint` catches only `PyMongoError`. A state that BSON cannot encode (non-string keys, ints above 64 bit) raises `bson.errors.InvalidDocument` or `OverflowError` instead of returning `"file"`. The campaign state is built from JSON-friendly values, so this is not reachable today.
- checkpoint_store.py:24-26 800 ms server selection and connect timeouts are short for a remote Atlas URI, so a slow but reachable cluster is treated as offline and falls back to the file. Latency-tuning choice, unchanged.
- contracts.py: apart from `IntegrationStatus` (imported by ebi_vcf/validator.py and biomni/adapter.py), no model in this file is imported anywhere. `ToolInvocationRequest`, `GenomicIncident`, `EvidenceReceiptV8` and others also exist in services/integrations/contracts.py with different fields; the runtime uses the integrations versions. Two divergent definitions with the same names is a maintenance hazard, but deleting or merging them is a refactor and was not done.

## VERIFIED OK
- `namespace_for` is deterministic, resolves relative paths and `..` segments, and is distinct per directory (tests).
- `_client` and `_database_name` follow `MONGODB_URI` and `MONGODB_DATABASE`, with the same defaults as config.py and mongodb/client.py. The v8 collections are written only to the configured database.
- `save_checkpoint` upserts a single document per namespace (replace semantics) and `load_checkpoint` returns only the `state` dict, never `_id`, and `None` for a missing or non-dict state (ADR-004).
- `claim_promotion` lets exactly one writer move the pointer off a given parent; a stale parent gets False; the next generation can claim from the new head; one pointer document per namespace (tested against local Mongo in the audit DB).
- Unreachable Mongo gives `"file"`, `None` and `False` (fail closed on promotion) without raising.
- contracts.py enums and models: `IntegrationStatus` values equal their names, `EvidenceReceiptV8` requires its mandatory fields and rejects unknown enum values, enum-valued fields coerce from strings; `datetime.now(UTC)` timestamps are timezone-aware. No `Any`-typed secret or path fields.
- Tests: services/tests/test_audit_v8_store_contracts.py (offline fake-client tests plus local Mongo tests in `diamond_audit_v8_store_contracts`, dropped afterwards). Existing coverage run: test_transfer_ablation.py, test_optimizer_gate.py, test_biomni_security.py, test_ebi_disagreement.py.
