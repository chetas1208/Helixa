# mongo_repo_rest audit (services/integrations/mongodb/repositories/*, except tasks_runs.py)

Files: `__init__.py`, `base.py`, `audit.py`, `datasets.py`, `events_checkpoints.py`, `evidence.py`, `harness_eval.py`.
Tests: `services/tests/test_audit_mongo_repo_rest.py` (isolated DB `diamond_audit_mongo_repo_rest`).

## FIXED
1. events_checkpoints.py:63-70 (`append_event`, run document sync): `$set seq_counter = seq` let a late write of a lower seq overwrite a higher one when concurrent appends reorder, leaving `runs.seq_counter` behind the true last sequence (reproduced with 50 concurrent appends: final 48/49 instead of 50, 3 of 10 runs). Test: `test_run_seq_counter_never_regresses_when_updates_reorder` (deterministic, delays the seq-1 sync). Fix: `$max: {seq_counter: seq}` (updated_at stays in `$set`).
2. harness_eval.py `list_versions` (and therefore `get_lineage` and `GET /api/harnesses`): `to_list(length=100)` silently dropped every harness version beyond the first 100 by `created_at`, i.e. the newest candidates/promotions vanished from the lineage graph with no signal. Test: `test_list_versions_and_lineage_are_not_truncated`. Fix: `to_list(length=None)`.
3. Same silent 100-document cap on methods that take no limit and promise "all": datasets.py `list_datasets`, `ArtifactRepository.list_by_dataset`, `ArtifactRepository.list_by_run`; events_checkpoints.py `list_checkpoints`; audit.py `MemoryRepository.list_by_run`. Tests: `test_list_datasets_not_truncated`, `test_list_artifacts_by_run_and_dataset_not_truncated`, `test_list_checkpoints_not_truncated`, `test_list_memories_by_run_not_truncated`. Fix: `to_list(length=None)`. (`EventRepository.get_events` and `IntegrationEventRepository.list_events` take an explicit `limit`, so they were left as is.)
4. datasets.py:17-34 (`get_dataset("default")`): the alias bypassed the DB lookup for the manifest's dataset id and always rebuilt the dataset from `fixtures/manifests/dataset_manifest.json` and `replace_one`-upserted it, overwriting the persisted document (any edited metadata/assembly/fixtures were lost, and `created_at` reset) on a plain read. Test: `test_get_dataset_default_alias_does_not_overwrite_persisted_dataset`. Fix: when the alias is used, return the already persisted dataset for the manifest's id if one exists; manifest sync only happens when nothing is persisted (unchanged behavior, covered by `test_get_dataset_manifest_fallback_syncs_when_not_persisted`).

## UNVERIFIED/NEEDS OTHER OWNER
- events_checkpoints.py:28-34 vs client.py:220 (`append_event` idempotency): the check-then-insert is not atomic. Reproduced (not committed as a test, it would fail): 5 concurrent `append_event(run, ..., idempotency_key="k")` produced 5 stored events with seq 1-5. No production caller passes an idempotency key today (`runner.emit_event` only forwards it). A real fix needs a unique partial index in client.py (`unique=True, partialFilterExpression={"idempotency_key": {"$type": "string"}}`; a plain unique sparse index would break because events without a key store an explicit `null`) plus catching `DuplicateKeyError` in `append_event` and returning the existing event. Owner: mongo_client + mongo_repo_rest.
- events_checkpoints.py:37-61: sequence allocation and event insert are separate operations; a crash between the `$inc` and the insert leaves a permanent gap in `seq` (ADR-003 states gapless). Cannot be fixed without transactions or a gap-tolerant reader contract; not changed.
- evidence.py:25-27 `get_receipt_by_run` and harness_eval.py:82-84 `get_by_run`: `find_one` without a sort on a non-unique `run_id`, so with several documents per run the pick is unspecified. Not reproduced (one receipt/evaluation is produced per run today); which document should win is a design decision.
- evidence.py:9-15 `save_receipt`: `replace_one` upsert by `receipt_id` would silently replace a stored receipt that shares an id but has a different digest. Receipt ids embed `time_ns`/uuid so a collision was not reproduced; sealed-receipt immutability is better enforced by an insert-only path, which would change the public behavior (the runner re-saves on resume). Left unchanged.
- datasets.py:75 `upsert_artifact` (and `ArtifactModel` unique on `artifact_sha256`): re-ingesting identical bytes for a second dataset/run replaces `dataset_id`/`run_id` on the single artifact document, so `list_by_dataset` for the first dataset loses it. A model/schema (mongo_models) decision.
- datasets.py:18 manifest path `fixtures/manifests/dataset_manifest.json` is relative to the process cwd; started from another directory the fallback silently returns `None`. Config/api_core decision. A malformed manifest raises `JSONDecodeError`/`ValidationError` out of `get_dataset` (not reproduced via a real code path, so unchanged).
- datasets.py:25 and models.py `declared_assembly` default `"GRCh38"` when the manifest lacks it (ADR-006 #4, already flagged by route_datasets); model default is mongo_models territory.
- harness_eval.py:32-59 `get_lineage`: `root_id` is only echoed back, nodes/edges are the whole forest (already noted by route_harnesses); changing it alters the response shape. `list_versions`/`MemoryRepository.list_by_run` sort on a timestamp only, so equal timestamps have unspecified relative order (not reproducible in practice with microsecond timestamps).
- base.py:26-28: `BaseRepository()` with no arguments constructs a `MongoDBClient` that the repository never closes; all in-repo callers pass `mongo=`/`db=`, so no leak was reproduced.

## VERIFIED OK
- `clean_doc` and every query use `{"_id": 0}` projections, so no ObjectId reaches callers (ADR-004); round trips for evidence, evaluation, mutation, integration-event repositories verified.
- `append_event`: atomic `$inc` counter, monotonic unique seq, sequential idempotency dedupe returns the first event, `get_events` paging (`after_seq`, `limit`), `get_latest_event`, missing run returns `[]`/`None`; invalid `limit <= 0` fails loudly with `ValueError` (not silently).
- Checkpoint `state` enum persists and reloads as `RunState`; `get_latest_checkpoint` picks highest `step_index`.
- `get_lineage` nodes/edges are correct for parent/child links; `list_events` ordering (newest first) and component filter.
- Dataset manifest fallback syncs only when nothing is persisted; unknown ids return `None`.
- ruff clean; existing suites for these modules (test_m01_durability, test_mongo_recovery, test_api_routes, route/orchestration/optimizer tests) pass with an isolated database.
