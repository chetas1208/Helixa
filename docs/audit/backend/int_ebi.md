# Audit: int_ebi (services/integrations/ebi_vcf/validator.py, __init__.py)

## FIXED
1. validator.py (assembly-checker phase, `pct_match` / PASS branch): the EBI tools write all their log output (including `Percentage of matches: N%`) to stderr, but the match rate was parsed from stdout only, so it always defaulted to 100.0. Report lines that are not REF mismatches (e.g. `Line 7: Chromosome chr99 is not present in FASTA file`, from `fixtures/invalid/unsupported_contig.vcf`) were silently dropped, and a crashed checker (real segfault with a junk FASTA, rc=139, empty report) also fell through to `assembly_valid=True` plus a PASS `reference_allele_concordance` ("100% concordance"). Tests (all failed before the fix): `test_contig_absent_from_fasta_is_not_reported_as_concordant`, `test_assembly_checker_crash_is_error_not_concordance`, `test_real_checker_segfault_on_garbage_fasta_is_not_pass`, `test_unparseable_match_percentage_is_error`, `test_match_percentage_on_stderr_below_100_is_fail`. Fix: parse the rate from stdout+stderr (unparsable such as `-nan%` stays None); non-mismatch report lines become FAIL `assembly_report_finding` checks; no findings with an unparsable rate, or 100% with a non-zero exit code, becomes an ERROR `assembly_checker_execution_error` (assembly_valid stays None, so the paired evaluator cannot reach AGREE_PASS). REF-mismatch parsing and the clean 100%/rc 0 PASS path are unchanged (`test_ref_mismatch_still_reported_with_locus`, `test_full_concordance_on_stderr_is_pass`, `test_ebi_disagreement.py`).
2. validator.py (`overall_valid`): `is_valid` stayed True while `overall_status == "ERROR"` when the assembly phase raised or errored (every other ERROR path returns `is_valid=False`). Covered by the `is_valid is False` assertions in the crash/-nan tests above. Fix: `overall_valid` also requires no ERROR check.

## UNVERIFIED/NEEDS OTHER OWNER
- CROSS-UNIT IMPACT (eval_paired owner): `services/tests/test_audit_eval_paired.py::test_divergence_collects_failures_from_both_engines` now fails (AGREE_FAIL instead of DISAGREE). It uses `fixtures/heldout/heldout_contig_mismatch.vcf` and only got DISAGREE because EBI wrongly reported PASS for a contig absent from the FASTA (defect 1). The oracle (`oracle.py` heldout_contig_mismatch_oracle) expects FAIL, so AGREE_FAIL is the scientifically correct verdict. That test needs another DISAGREE fixture/stub (e.g. the policy-without-REF-check approach in `test_ebi_disagreement.py::test_policy_without_ref_check_disagrees_with_ebi`). Not edited (not my file). Recorded `artifacts/v8/*.json` were generated from ref_mismatch/valid fixtures and are unaffected, but I did not regenerate anything.
- validator.py:~318 (mismatch regex `Chromosome\s+([A-Za-z0-9_]+),`): contigs containing `.`, `-` or `*` (e.g. `NC_000001.11`, `HLA-A*01:01`) do not match, so those REF mismatches are now reported as generic FAIL `assembly_report_finding` (still FAIL, no longer lost) but without structured chrom/pos/ref/expected. Not changed (no failing wrong-verdict case).
- validator.py (assembly phase gate): when `fasta_path` is given but missing, or the assembly binary is not executable, phase 2 is silently skipped (`assembly_valid=None`, overall PASS). Downstream `PairedScientificEvaluator` handles it (INCONCLUSIVE) and `test_audit_eval_paired.py` covers it, so left as designed.
- validator.py: `raw_validator_stdout` / `raw_assembly_stdout` are always empty because the tools log to stderr; the stderr is not recorded in the report. Adding a field changes the report schema, so not done.
- validator.py: the assembly checker creates a missing `<fasta>.fai` next to the FASTA (observed: "Creating index from input FASTA file"), a write outside scratch. Callers should supply an indexed FASTA; not changed.
- validator.py: `checksums_match()` re-hashes both ~7 MB binaries on every `is_available()`/`get_version()` call (several times per `validate`), and there is a hash-then-exec TOCTOU window. Performance/hardening only, no wrong result shown.
- validator.py: subprocess env is not sanitized and stdout/stderr capture is unbounded (ADR-010 explicitly scopes this to BcftoolsAdapter), so left alone.

## VERIFIED OK
- Subprocesses use argv lists (no shell), timeouts on both phases (TimeoutExpired -> ERROR report), scratch output dir via TemporaryDirectory (cleaned), VCF/FASTA paths passed as values of `-i`/`-f`.
- Syntax verdict: real validator output is in the summary file (stdout is empty); valid/malformed/truncated fixtures give correct valid/not-valid, and "not valid" always wins over "valid".
- Binary SHA-256 pin enforced before any run; missing/mismatched binary yields an ERROR report, not a PASS. Missing VCF yields ERROR. `get_version` parses the stdout `version X` line.
- REF mismatch fixture yields `reference_allele_mismatch` with locus `chr22:105002`; input VCF bytes are not modified (covered by `test_ebi_disagreement.py`).
- Statuses never claim genome-build identity; missing FASTA does not run the assembly phase (ADR-006/ADR-016 stance preserved).
